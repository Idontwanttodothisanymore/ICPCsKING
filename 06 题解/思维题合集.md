**[2274F Aura Battle](https://codeforces.com/contest/2274/problem/F)**

> **交互题。** 有一个隐藏的 $x$，每次选择 $a,b$，交互库告诉你这次操作的代价：$$\min(|x-a|,|x-b|)$$一共有 $10$ 轮，你需要合理的选择 $a,b$ 最小化代价之和，使得你的答案与最优解不能差超过 $67$ 。

神题。
##### 构造策略

交互库总会返回 $x$ 到 $a,b$ 的距离的最小值。想办法均摊这个值，使得无论何种情况，这个值不会太大。自然的考虑到把 $n$ 分为 $4$ 块。 取 $a=2500$ 和 $b=7500$，这样可以保证返回的 $p\leq 2500$。

此时的 $x$ 有 $4$ 个可能的位置，即 $\{a+p,a-p,b+p,b-p\}$。确定 $x$ 的位置的收益是非常高的，因为这可以保证以后的轮次的代价均为 $0$，甚至不用完全确定，只需要保证只有两个可能的位置即可。

于是我们考虑设计询问缩小其可能出现的位置。让第二次询问的值产生一点偏移， $a=2501$ 与 $b=7502$。这样最后的结果会出现 $\{p-1,p+1,p-2,p+2\}$ 中的一种，据此就可以确定 $x$ 的位置了。

两次操作的极限情况是 $p+p+2\leq 2500\times 2+2=5002$。这确实有点大了，~~因为交上去不对。~~

考虑如何优化，上面的代价计算的式子在 $p$ 变大的增加，说明瓶颈主要在 $x$ 远离 $a,b$ 的时候出现。因此考虑在 $p\geq 1250$ 时改变询问方式。具体而言，我们固定 $a=5000$，这样 $x$ 在中间两个位置时可以保证 $p\leq 1250$。接下来要选一个 $b$，使得 $x<1250$ 和 $x>8750$ 时 $p\leq 1250$。~~抱歉长官这太难了~~。容易发现这是不可能的。

造成这不可能的根本原因是什么？因为这种完全对称的结构将需要操作的区间分为了左右两半。而我们没有足够的操作数量可以顾及这两半。因此我们尝试构造不对称的 $a,b$，使得有一半区间在之前被处理掉。

重新考虑分配方式，上一世我将 $n$ 分为八块（最开始 $4$ 块之后优化时讨论 $p$ 的位置变为 $8$ 块），这次我们删掉一个，使其变为七块。在重新按照上面的流程走一遍。

这次的第一次操作取 $a= \frac{10000}{7} \approx1429,b= \frac{5\times10000}{7} \approx7143$。

- 如果 $p\leq 1428$，那么第二次询问 $a'=a+1,b'=b+2$，原因如前文所说。此时得到的最劣代价为 $2p+2\leq 2858$；
- 如果 $p>1429$，那么说明 $x$ 在 $[1429\times 2,1429\times 4]$ 或 $[1429\times 6,1429\times 7]$ 里，这样就好办了！我们仍然制造一些偏移： $a'=1429\times 3-1$ 与 $b'=1429\times 6 + 2$，观察得到的 $p$ 的偏移量即可得到 $x$ 的值。此时的最劣代价是 $p+1429\times 3-p-1429=2858$。

因此，我们得到一个最劣代价为 $2858$ 的策略。上面的分析针对边界情况不严谨，但是由于题目放的比较松，所以问题不大（）

##### 下界证明

**这是本题最难的一部分**。由于我们的策略最劣代价为 $2858$，所以需要证明最优策略的最劣代价 $m\geq 2858-67$。这样我们的策略才是正确的。

设最优策略所选择的 $a<b$，第一次选择时需要满足 $p\leq 2791$，否则是平凡的。

因此，$a,b$ 的取值存在一些限制，$[a-2791,a+2791]\cup [b-2791,b+2791]$ 需要覆盖整个区间，否则一定存在一个 $x$，使得第一轮的代价就超了。

简单写一下此时要满足 $\begin{cases}a\leq 2791\\b\geq 7209 \\b-a\leq 2791\times 2\end{cases}$ 即 $\begin{cases} 1628\leq a\leq 2791 \\7209\leq b \leq 8343\end{cases}$，定义：
$$
p=\min\left( a-1,10000-b,\left\lfloor  \frac{b-a}{2}  \right\rfloor  \right)
$$
可知 $p\geq 1627$。

此时有四个候选值：$\{a-p,a+p,b-p,b+p\}$。这四个值都在合法范围内，因此第一轮无法区分。

最左边的候选值与其他的候选值的距离至少为 $2p$，最右边也一样。因此要第二步同时处理左右两个端点。这样又不能保证对中间两个点都保证距离小于 $p$。因此第二轮至少损失 $p$。

由此，此时的最劣代价为 $p+p\geq 3254$。与假设矛盾。

综上，最优策略的最劣代价为 $n\geq 2791$。$\square$

由此可以发现，题目给的要求是很松的，事实上可以证明 $m\geq 2857$，这说明我们的策略与最优策略几乎无异。

##### 代码实现

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 10000;
const int a = 1429;
const int b = 7143;

int dist(int x, int c, int d) {
    return min(abs(x - c), abs(x - d));
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;

    while (t--) {
        cout << a << ' ' << b << endl;

        int p;
        if (!(cin >> p)) return 0;

        vector<int> s;

        for (int x : {a - p, a + p, b - p, b + p}) {
            if (x < 1 || x > N) continue;
            if (dist(x, a, b) == p) {
                s.push_back(x);
            }
        }

        sort(s.begin(), s.end());
        s.erase(unique(s.begin(), s.end()), s.end());

        int c, d;

        if (p <= 1428) {
            c = 1430;
            d = 7147;
        } else if (p <= 2855) {
            c = 4287;
            d = b + p;
        } else if (p == 2856) {
            c = 4287;
            d = 10000;
        } else {
            c = 4286;
            d = 9999;
        }

        cout << c << ' ' << d << endl;

        int q;
        if (!(cin >> q)) return 0;

        int x = -1;

        for (int y : s) {
            if (dist(y, c, d) == q) {
                x = y;
                break;
            }
        }

        if (x == -1) return 0;

        for (int i = 2; i < 10; ++i) {
            cout << x << ' ' << x << endl;

            int unused;
            if (!(cin >> unused)) return 0;
        }
    }

    return 0;
}
```
